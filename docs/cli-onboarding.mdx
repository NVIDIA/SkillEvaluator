Bring SkillEvaluator to the repository where you build skills. Answer a few
questions; the CLI prepares your workflows, report hosting and setup pull request.
Your CI runs Tier 1 checks, including **SkillSpector security scanning**.

```bash title="After activating the preview environment"
skillevaluator ci init
```

<Note>
  **Onboarding preview.** These commands are in the supplied local test build,
  not the published PyPI 0.7.0 package. This review build supports the prepared
  public GitHub test repositories with admin access. For the released path,
  [copy a GitHub Actions template](/skills/skillevaluator/github-actions#get-started).
</Note>

## What the CLI handles

| You choose | The CLI prepares |
| --- | --- |
| Skill folders and score threshold | A workflow that checks your selected skills. |
| Changed skills or all skills | The pull-request scan configuration. |
| Hosted reports and PR comments | Report hosting, the publisher workflow and its approval settings. |
| Create a setup PR | A branch and PR you can review before merging. |

You do not copy evaluator code into your repository or install CI scanners
locally. The shared image supplies the runtime. This setup runs **Tier 1**;
Tier 2 and Tier 3 are not part of this setup.

## Run the wizard

Start from a clean checkout of your test repository. The CLI uses your existing
[GitHub CLI](https://cli.github.com/) login; run `gh auth login` if you have not
signed in. GitHub Actions and the referenced reusable workflows must be allowed.

<Tabs>
  <Tab title="Prepared preview environment">
    From the prepared checkout, use its installed CLI directly:

    ```bash
    .env/bin/skillevaluator ci init
    ```

    This keeps the preview separate from an older global installation.
  </Tab>
  <Tab title="Install the supplied preview package">
    Use Python 3.12–3.14 and the preview wheel supplied with this review.
    Replace the example wheel path with its location on your machine.

    ```bash
    python3.12 -m venv .venv
    source .venv/bin/activate
    python -m pip install /path/to/skillevaluator-0.7.1.dev3-py3-none-any.whl
    skillevaluator ci init
    ```

    A normal `pip install skillevaluator==0.7.0` does not install these preview
    commands.
  </Tab>
</Tabs>

The interview has five short questions. Press **Enter** to keep a default.

| Question | Example answer | Meaning |
| --- | --- | --- |
| **Skill folders** | `1,2` or `1 2` | Select folders 1 and 2 from the discovered list. |
| **Minimum score** | `70` | Fail the quality check below 70/100. |
| **PR scan scope** | `auto` | Check changed skills; choose `all` for the full selection. |
| **Hosted feedback** | `y` | Add hosted HTML and an updated PR comment. |
| **Apply the setup** | `pr` | Configure GitHub and open the setup PR after confirmation. |

Required security and schema checks remain independent of the quality score.
The default checks use no model key.

<Accordion title="I want to inspect the plan first">
  Run `skillevaluator ci init --mode preview` using the same environment. It
  discovers skills and shows the plan without writing files or changing GitHub.
  The `save` option writes workflow files locally but does not configure the
  remote settings; choose `pr` for the full guided setup.
</Accordion>

## Review and merge

After you confirm, the CLI configures the selected GitHub settings and opens a
setup PR. Review the files, then merge the PR into your default branch.

<Frame caption="The setup is a reviewable change to your own repository.">
<div style={{ padding: "16px", width: "100%", minWidth: 0 }}>

**Setup PR**

```text
.github/workflows/
├── skill-checks.yml             Checks + downloadable reports
└── publish-skill-reports.yml    Optional hosting + PR comment
```

**Your next action:** review and merge the setup PR.

</div>
</Frame>

The publisher must be on the default branch before it can comment on a new
skill PR. A setup-only run may be **Skipped** because no skill changed.

## Try a skill change

<Steps>

### Open a test PR

With hosted feedback enabled, merge setup and run the **exact demo command
printed by the wizard**. In the prepared preview environment it is:

```bash
.env/bin/skillevaluator ci demo
```

The CLI asks before adding a small Markdown comment to one configured
`SKILL.md` on a new branch. Choose `y` to create the PR or press Enter to skip.
You can also make a small skill edit and open a PR yourself; use this manual
route for a checks-only setup.

### Read the feedback

| On the PR | What you will find |
| --- | --- |
| **Checks → Skill checks** | The scan result for that commit. |
| **Conversation**, with publishing enabled | The bot comment, after report publication completes. |
| **Open full report** in that comment | Findings, scores and detailed HTML for the scan. |

**Checks only:** open the scan in **Actions**, download its report artifact,
extract it, and open `index.html`.

### Finish the test

Push another small change to rerun the check; with publishing enabled, the same
bot comment updates. Close the test PR when finished; **you do not need to merge it**.

</Steps>

A failed check can still produce a report. Read the finding: it may describe a
skill issue or a scanner that did not finish. A setup PR being merged is not a
passing evaluation.

## A few useful details

<AccordionGroup>
  <Accordion title="What access does this preview need?">
    Use the prepared public GitHub test repository with a clean checkout and
    repository admin access. The local preview is deliberately restricted to
    the prepared personal test namespace. It does not yet provide GitLab CLI
    onboarding, organization-wide enrollment or private report hosting.
    The wizard preserves unrelated workflows and existing branch rules.
  </Accordion>
  <Accordion title="Where are reports hosted?">
    Hosted reports use the repository's GitHub Pages site. Reports can contain
    source excerpts and unmerged findings, so the wizard confirms public
    hosting before applying it. Choose checks only for downloadable artifacts.
    The preview uses the official CI scanner image and a pinned publisher
    candidate from [PR #326](https://github.com/NVIDIA/SkillEvaluator/pull/326).
    That publisher is not part of the `ci-0.7.0` release bundle.
  </Accordion>
  <Accordion title="The terminal says No such command ci">
    Your shell may have selected an older installation. Use the explicit
    environment path shown by the wizard, such as
    `.env/bin/skillevaluator ci demo`, from the same repository. Changing
    directories does not activate that directory's virtual environment.
  </Accordion>
  <Accordion title="A scan ran, but there is no comment">
    Confirm that setup is merged, the PR is open, and its branch is in the same
    repository. Wait for **Publish skill reports** to finish. Open its run if
    publication failed. Fork-origin PRs keep their available results in Actions.
    With checks only, comments are not configured; download the report artifact
    from the scan run instead.
  </Accordion>
  <Accordion title="Does this make Skill checks a required merge check?">
    No. After the first run, select its scan check in your GitHub branch rules
    if a failed or incomplete result should block merging. The current template
    emits `skills / Tier 1 scan`; use the actual check name shown in your repository.
  </Accordion>
</AccordionGroup>
