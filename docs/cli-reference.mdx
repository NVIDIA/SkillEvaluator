If you want task-oriented guidance instead, start from the tier guides: [Tier 1: Validation](/skills/skillevaluator/tier1-validation), [Tier 2: Deduplication](/skills/skillevaluator/tier2-deduplication), and [Tier 3: Live Evaluation](/skills/skillevaluator/tier3-live-evaluation).

commands referenced below.

## tier3 import-metrics

```bash
skillevaluator tier3 import-metrics INPUT.json --output-dir NEW_DIRECTORY
```

`INPUT.json` must exist. Required `-o, --output-dir` names a directory that must
not exist. The command validates the complete input before writing
`external_metrics.json` and `external_metrics.md`. It never executes tests or
assigns canonical scores; exit 0 means a valid import, not passing tests.
See the [input contract and simulator example](/skills/skillevaluator/custom-graders#import-precomputed-custom-metrics).

## Global conventions

**Reports.** Every Tier 1 and Tier 2 command accepts the same two report options.
Direct `tier1 PATH`, `tier1 validate PATH`, and `tier2 PATH` default to
`cli,json,html`; focused expert commands default to `cli`:

| Flag | Default | Effect |
| --- | --- | --- |
| `-r, --report [cli\|json\|html\|markdown\|sarif]` | `cli,json,html` for direct workflows; `cli` for focused commands | Report format(s). Accepts comma- or space-separated values (`-r cli,json,html` or `-r cli json html`) and may be repeated. The compact default view writes html+json unless `-r` is passed explicitly, which is honored exactly (including `cli`). |
| `-o, --output-dir DIRECTORY` | `reports` | Directory for generated reports. |

In practice: a default `validate` run (no `-r`) shows the compact pipeline view **and** writes `json` + `html` report files; passing `-r` takes over completely — `-r cli` really means terminal output only, no files. The focused expert commands take the `cli` default literally: they print the full terminal report and write files only for the formats you request with `-r`. A `validate` run writes `skillevaluator-output-<timestamp>.json` / `.html` (plus `.md` with `-r markdown` or `.sarif.json` with `-r sarif`); standalone commands write a fixed `skillevaluator-<kind>` basename (for example `skillevaluator-quality.json`), so a re-run overwrites the previous report. Direct workflows write `skillevaluator-tier1` or `skillevaluator-tier2` reports in the selected formats and also overwrite previous files with that basename. Filename conventions and report anatomy live in [Reports & Results](/skills/skillevaluator/reports).

**Exit codes.** Commands communicate through a small exit-code contract — this is what your CI gates on (see [Gate Your CI](/skills/skillevaluator/ci-integration)):

| Code | Meaning |
| --- | --- |
| `0` | Success |
| `1` | Validation failed, the run could not complete, or an unexpected internal error occurred |
| `2` | Usage error — an unknown flag, a value outside an option's type or choices, or a target path that does not exist |

**Global options.** `skillevaluator --version` prints the installed version. `-v, --verbose`, given before the command (`skillevaluator -v validate ./my-skill`), enables debug logging; for `validate` it also replaces the compact pipeline view with the full detail stream. Every command accepts `-h` as a short form of `--help`.

## Direct tier workflows

```bash title="Run each tier independently"
skillevaluator tier1 ./my-skill
skillevaluator tier2 ./my-skill --catalog ./skill-catalog.json
skillevaluator tier3 ./my-skill
```

There is no required `run` subcommand. A bare `tier1`, `tier2`, or `tier3` shows
help and does not evaluate the current directory. Prefix a path with `./` when
its name matches an expert command: `tier1 ./validate` evaluates a directory
named `validate`; `tier1 validate ./my-skill` invokes the Tier 1 workflow.

| Workflow | Default scope | Scope controls |
| --- | --- | --- |
| `tier1 PATH` | All static checks including dependencies; rubric, LLM security, and finding verification when a provider is configured | `--no-llm` skips LLM stages; `--llm` requires provider access; `--checks` selects static checks |
| `tier2 PATH` | Intra-skill analysis | `--catalog FILE` adds inter-skill comparison against a saved JSON catalog; without it, inter-skill is explicitly not run |
| `tier3 PATH` | One missing starter case is generated, then the provider-native agent runs in Docker with and without the skill | Accepts the [tier3 evaluate](#tier3-evaluate) options; missing-source generation is implicit |

Direct Tier 1 can run keyless, but marks its LLM stages as skipped. Missing
required scanner evidence remains incomplete. Direct Tier 2 needs both chat and
embedding access and takes one skill, not a collection. Create its catalog with
`similarity-check ./skills --save-catalog ./skill-catalog.json`. Direct Tier 3
preserves valid existing sources and rejects invalid ones; it does not overwrite
a dataset to repair it.

`validate PATH` runs all three tiers for skills by default, including Tier 3
autopilot. It is separate from these tier-only workflows.

### Direct tiers compared with `validate --tiers`

`validate --tiers` narrows the combined pipeline; it does not run a tier on
its own. Tier 1 always runs and gates the exit code, so `--tiers 2`,
`--tiers 3`, and `--tiers 2,3` are rejected. Use `tier2 PATH` or
`tier3 PATH` to run Tier 2 or Tier 3 without Tier 1.

| | Direct workflows | `validate PATH --tiers ...` |
| --- | --- | --- |
| Tiers run | Only the named tier | Tier 1 plus any selected tiers |
| Tier 1 dependency audit | Included in `tier1 PATH` | Opt-in with `--checks`, which replaces the default list, so name every check you want plus `dependency` ([selection rules](/skills/skillevaluator/tier1-validation#narrow-to-specific-checks)) |
| Tier 1 LLM stages | Rubric, LLM security, and verification run when a provider is configured; `--no-llm` skips them | LLM security analysis runs only with `--llm`, and finding verification only with `--llm-verify`; no rubric stage |
| Reports | `tier1` and `tier2` default to `-r cli,json,html` and write `skillevaluator-tier1.*` or `skillevaluator-tier2.*` under `-o`. `tier3` writes its run under `--results-dir` and does not accept `-r` or `-o` | The compact view writes HTML and JSON as `skillevaluator-output-<timestamp>.*`; skill targets also get `BENCHMARK.md` |
| Exit code `1` | `tier1`: a check failed or required evidence is incomplete. `tier2`: HIGH or CRITICAL findings or a blocking analysis error. `tier3`: the run did not complete; a `FAIL` verdict alone exits `0` | Tier 1 failed; Tier 2 findings unless `--no-block-on-dedup`; Tier 3 only with `--block-on-agent-eval` |

For `tier2 PATH`, `tier3 PATH`, and `tier1 PATH --llm`, a missing provider is
a configuration error that exits `1` before any report is written. `tier1 PATH`
without `--llm` runs keyless. `validate` records Tier 2 and Tier 3 as skipped
and still writes its reports.

Direct Tier 3 checks provider, option, and runtime configuration before it
generates a starter case, so a configuration error leaves `evals/` unchanged and
no paid generation or agent run starts. The exception is `--env-mode` `ack`,
`cwsandbox`, `langsmith`, `openshift`, and `wandb`: their backend checks contact
a remote control plane, so they run after the starter case is generated. Usage
errors, such as an option the workflow does not accept, exit `2`.

### Direct Tier 1 options

| Flag | Default | Effect |
| --- | --- | --- |
| `--checks TEXT` | All applicable static checks, including dependency auditing | Comma-separated subset of static checks |
| `--skip CHECKS` | none | Comma-separated checks to leave out, e.g. `secrets` for the Gitleaks scan. Skipped checks are shown and reported as skipped, nothing is installed for them, and the run cannot certify Tier 1 for publication |
| `--llm / --no-llm` | Enabled when a provider is configured | Enable or skip rubric, LLM security, and finding verification; explicit `--llm` requires valid provider configuration |
| `--min-score INTEGER` | `70` | Minimum passing quality and rubric score, from 0 to 100; quality severity overrides cannot waive the minimum |
| `--quality-config PATH` | packaged `quality-default.yaml` | YAML file that adjusts the quality check's expected headings and error-handling rules; settings it omits keep their packaged values. See [Tier 1: Validation](/skills/skillevaluator/tier1-validation#the-checks). |
| `--pii-waivers PATH` | none | Reviewed, expiring PII waivers applied by the `pii` check. See [PII waivers](/skills/skillevaluator/tier1-validation#pii-waivers). |
| `--profile TEXT` | `SKILLEVALUATOR_PROFILE`, then `default` | Validation policy: `default` or `registry`. `external` is a compatibility alias for `default`. |
| `--policy FILE` | none | Explicit policy overlay, including reviewed ownership-contact severity. See [Tier 1 policies](tier1-validation.mdx#validation-profiles-and-policies). |
| `--previous-version TEXT` | `SKILLEVALUATOR_PREVIOUS_VERSION`, else unset | Previous version for version checks |
| `--skillspector-baseline FILE` | unset | Audited SkillSpector suppression baseline; never discovered from the skill. See [Audited SkillSpector baselines](/skills/skillevaluator/tier1-validation#audited-skillspector-baselines). |

Also accepts `-r/--report` and `-o/--output-dir` described above.

### Direct Tier 2 options

| Flag | Default | Effect |
| --- | --- | --- |
| `--catalog FILE` | unset | Saved JSON catalog for inter-skill comparison |
| `--threshold FLOAT` | `0.80` | Intra-skill candidate similarity threshold |
| `--similarity-threshold FLOAT` | `0.75` | Inter-skill reporting threshold |
| `--full-body` | off | Compare the full `SKILL.md` against a catalog created in full-body mode |

Both thresholds accept values from 0 to 1. Also accepts `-r/--report` and
`-o/--output-dir`. Direct Tier 3 accepts the options in
[tier3 evaluate](#tier3-evaluate), with missing-source generation already enabled.

## Expert tier subcommands

The commands below remain available for focused operations.
`skillevaluator tier1 validate PATH` runs the same isolated Tier 1 workflow
as `tier1 PATH`. Use top-level `skillevaluator validate PATH` for the combined
pipeline.

| Group | Members |
| --- | --- |
| `tier1` | `validate`, `quality-check`, `rubric-eval`, `security-scan`, `pii-scan`, `lint-scripts` |
| `tier2` | `context-optimization-check`, `dedup-scan`, `similarity-check` |
| `tier3` | `evaluate`, `interact`, `select-decoys`, `create-eval-dataset`, `migrate-dataset`, `init-custom-grader`, `init-harbor-task`, `doctor`, `view`, `compare`, `feedback`, `validate`, `harbor-view`, `import-metrics`, `import-traces`, `accept-traces` |

`health-check` and [models](#models) are top-level only. The expert commands
[tier3 evaluate](#tier3-evaluate), [tier3 select-decoys](#tier3-select-decoys),
[tier3 feedback](#tier3-feedback), [tier3 import-metrics](#tier3-import-metrics),
[tier3 import-traces](#tier3-import-traces),
[tier3 accept-traces](#tier3-accept-traces), and `tier3 validate` are advertised
**only** inside the `tier3` group:

### tier3 import-traces

Import a production trace export into redacted candidates outside the skill.
See [Trace Datasets](/skills/skillevaluator/trace-datasets) for the v1 JSON/JSONL contract and redaction limits.

```bash
skillevaluator tier3 import-traces ./my-skill ./sessions.jsonl -o ./review
```

| Option | Default | Purpose |
| --- | --- | --- |
| `-o`, `--output DIR` | `./<skill-dir-name>-trace-review` | Review bundle directory, outside the skill. |
| `--force` | off | Overwrite an existing candidates file. |
| `--dry-run` | off | Print classifications, warnings, and the next-step hint; write nothing. |

### tier3 accept-traces

Promote only explicitly reviewed candidates into `evals/evals.json`. Requires
`SKILL_PATH` and `REVIEW_DIR`. `accept` requires a reviewer-written expectation;
`accept_observed` is allowed only for successful sessions with non-empty output.
Pending and rejected candidates are skipped. All decision/redaction errors abort
before writing; dataset validation errors after writing return a non-zero status.

```bash
skillevaluator tier3 accept-traces ./my-skill ./review --dry-run
skillevaluator tier3 accept-traces ./my-skill ./review
```

| Option | Default | Purpose |
| --- | --- | --- |
| `--dry-run` | off | Report additions and already-present ids without writing. |
| `--allow-native-harbor` | off | Explicitly accept traces when native Harbor tasks are selected. |

### tier3 validate

Validate the Tier 3 `evals/` directory and the optional Harbor bring-your-own-task contract before you spend money on a live run. The dataset and directory rules it enforces are documented in [Eval Datasets](/skills/skillevaluator/eval-datasets). Because the no-skill baseline is graded on the same text, it warns when a case's prompt points at `skills/<name>`, `<name>/SKILL.md` or reading or following `SKILL.md`, or when its expected output or an assertion names those files, calls `<name>` a skill, says the agent used, invoked or identified `<name>`, or runs one of the skill's scripts from `scripts/` or `tools/`. The check is a wording heuristic, and these warnings fail the command only with `--strict`.

```bash title="Check evals/ before a live run"
skillevaluator tier3 validate ./my-skill --strict
```

| Flag | Default | Effect |
| --- | --- | --- |
| `--json` | off | Emit JSON output. |
| `--strict` | off | Treat warnings as failures. |
| `--harbor-contract` | off | Validate the Harbor task and reward contract (see [Custom Graders & Tasks](/skills/skillevaluator/custom-graders)). |

## validate

Validate a skill, rule, workflow, or plugin. For skills, all three tiers run by default. Tier 3 uses autopilot to reuse an existing evaluation source or generate one starter case when none exists; invalid sources are reported rather than replaced. Tier 1 static, security, and quality checks always gate the exit code. Tier 2 deduplication runs and gates by default, but `--no-block-on-dedup` keeps the scan while making its findings advisory. Tier 3 is advisory unless `--block-on-agent-eval` is set. Rules, workflows, and plugins retain their applicable validation stages without automatically enabling live skill evaluation.

```bash title="Common invocations"
skillevaluator validate ./my-skill                        # Tier 1 + Tier 2 + Tier 3 autopilot
skillevaluator validate ./my-skill --llm                  # add LLM security analysis
skillevaluator validate ./my-skill -r cli,json,html       # multiple report formats
skillevaluator validate ./my-skill --no-dedup             # skip Tier 2 dedup
skillevaluator validate ./my-skill --no-block-on-dedup    # run Tier 2 as advisory
skillevaluator validate ./my-skill --profile default      # standard validation policy
skillevaluator validate ./my-skill -a codex               # choose the Tier 3 agent
skillevaluator validate ./my-skill -a codex \
    --block-on-agent-eval                                  # gate on Tier 3 too
skillevaluator validate ./my-skill --no-autopilot         # require an existing eval source
skillevaluator validate ./my-skill --full -a codex        # compatibility: same default scope
skillevaluator validate ./my-skill --tiers 1,2            # skip live evaluation
skillevaluator validate ./my-skill --tiers 1              # static checks only
skillevaluator validate ./my-skill --tiers 1,3            # explicit tier selection
skillevaluator validate ./skills-folder                   # whole catalog, serially
skillevaluator validate ./my-skill -a codex,claude-code \
    --env-mode docker --harbor-keep-jobs                  # Tier 3, retain Harbor jobs
```

Pointing `validate` at a directory of skills (one with no root `SKILL.md`) runs the whole pipeline for each skill inside it, writes each skill's reports under `<output-dir>/<skill>/`, and finishes with a per-skill summary — catalog validation in one command. Skills run serially by default; `--workers N` validates up to N skills at once in parallel processes. `--previous-version` is rejected for a directory of skills. By default the terminal shows a compact pipeline view; `--verbose` switches to the full per-check detail stream.

`--help` groups the flags into four panels, mirrored by the subsections below.

### Run & Reports

Applies to the whole run: target typing, policy profile, reports, tier selection.

| Flag | Default | Effect |
| --- | --- | --- |
| `--type [skill\|rules\|workflows\|plugin\|auto]` | `auto` | Force the content type instead of auto-detecting it from the target path. |
| `--tiers TEXT` | all three for skills | Explicit tier selection, e.g. `--tiers 1,2` skips live evaluation and `--tiers 1,3` skips dedup. Tier 1 always runs. |
| `--full` | unnecessary for skills | Compatibility flag for all three tiers with autopilot. Explicit tier selection and disable flags still apply. |
| `--verbose` | off | Print the full per-check detail stream instead of the compact pipeline view. |
| `--profile TEXT` | `$SKILLEVALUATOR_PROFILE`, then `default` | Bundled validation policy: `default` or `registry`. `external` is a compatibility alias for `default`. |
| `--external` | — | Compatibility alias for `--profile default`; does not change repository visibility. |
| `--policy FILE` | none | Custom policy YAML overlaid on top of `--profile`. |
| `--workers INTEGER RANGE` | `1` | Concurrent skill jobs when validating a folder of skills (`x>=1`). Values above 1 run skills in parallel processes and disable the per-skill pipeline view. |

The [evaluated source provenance](#evaluated-source-provenance) flags also appear in this panel.

Auto-detection recognizes: a `SKILL.md` for skills, `.mdc` files for rules, `workflow-rules.mdc` for workflows, and — for plugins — a bundle-reference `agent_plugin.yaml`/`.yml` manifest or a contained `.claude-plugin/plugin.json` manifest. Plugins are validated against their public contract; quality, lint, and version checks are skill-only and skipped for plugins.

When auto-detection finds none of these, the type is `unknown`. Tier 1 then records the `schema`, `version`, and `quality` checks as not applicable (N/A) instead of failing them with `No skills found`, and still runs the content scans. Tier 1 passes when those scans pass; Tier 2 still runs on the target unless `--no-dedup` or `--tiers 1`. The JSON report adds a root `tier1_applicability` object, whichever checks the run selects. Auto-detection also reads the directory names in the target's absolute path, so a repository whose path includes a directory named `skills`, `team-skills`, `team-rules`, `workflows`, or `team-workflows` is detected as that type, not `unknown`. A target folder whose own `SKILL.md`, `workflow-rules.mdc`, `agent_plugin.yaml`/`.yml`, or `.claude-plugin/plugin.json` is mis-cased (such as `Skill.md`) or a dangling symlink still runs the manifest checks, and fails them. A mis-cased manifest below the target is not discovered; validate that folder directly. Pass `--type` to validate the target as a given type anyway. See [Content types](/skills/skillevaluator/tier1-validation#content-types).

`validate` also takes the standard `-r/--report` and `-o/--output-dir` options described under [Global conventions](#global-conventions).

### Tier 1 · Static & Security

Static checks; LLM-free by default. Tier 1 gates the exit code and always runs.

| Flag | Default | Effect |
| --- | --- | --- |
| `--checks, --tier1-checks TEXT` | all applicable | Comma-separated subset of Tier 1 checks. Default choices: `schema`, `version`, `security`, `pii`, `license`, `code-integrity`, `unicode`, `quality`, `lint`; opt-in (not run by default): `dependency`. `quality`/`lint`/`version` are skill-only and skipped for rules and workflows. |
| `--skip CHECKS` | none | Comma-separated Tier 1 checks to leave out: any check above or `secrets` (the Gitleaks scan inside `code-integrity`). Skipped checks show as skipped in the terminal and reports, nothing is installed for them, and the run cannot certify Tier 1 for publication. |
| `--previous-version VERSION` | `SKILLEVALUATOR_PREVIOUS_VERSION`, else unset | Previous released version; the skill's version must be a strictly greater SemVer. Single-skill targets only. |
| `--fail-fast` | off | Stop on the first failing check instead of collecting all issues. |
| `-c, --continue-on-failure` | off | Run the full pipeline without stopping early; record all issues in the reports. Overrides `--fail-fast`, and for folder validation keeps scanning every skill past a CRITICAL finding. |
| `--llm, --tier1-llm / --no-llm, --no-tier1-llm` | `no-llm` | Enable LLM-backed security analysis (requires a configured public provider — see [Providers & Credentials](/skills/skillevaluator/configuration)). |
| `--llm-verify` | off | Run a second LLM pass to suppress false-positive findings. |
| `--skillspector-baseline FILE` | unset | Audited SkillSpector suppression baseline for the `security` check; never discovered from the skill. See [Audited SkillSpector baselines](/skills/skillevaluator/tier1-validation#audited-skillspector-baselines). |
| `--min-score INTEGER` | `70` | Minimum quality score (0–100) required per skill when the `quality` check runs; policy severity overrides cannot waive this gate. |
| `--quality-config PATH` | packaged `quality-default.yaml` | YAML file that adjusts the quality check's expected headings and error-handling rules; settings it omits keep their packaged values. See [Tier 1: Validation](/skills/skillevaluator/tier1-validation#the-checks). |
| `--pii-waivers PATH` | none | Reviewed, expiring PII waivers applied by the `pii` check; forwarded to each skill of a catalog run. See [PII waivers](/skills/skillevaluator/tier1-validation#pii-waivers). |

### Tier 2 · Deduplication

Embedding + LLM dedup; on by default, skips gracefully without a provider key.

| Flag | Default | Effect |
| --- | --- | --- |
| `--dedup, --tier2 / --no-dedup, --no-tier2` | `dedup` | Run Tier 2 intra-skill semantic-overlap checks. On by default; skipped gracefully without public embedding access. Use `--no-tier2` (or `--no-dedup`) to disable. |
| `--block-on-dedup / --no-block-on-dedup` | blocking | Choose whether Tier 2 findings participate in the `validate` exit gate. The scan and its report entries still run with `--no-block-on-dedup`. |

### Tier 3 · Live Agent Evaluation

<Note>
The following flags are forwarded to the live-eval engine when Tier 3 is enabled, which is the default for skills. They do not re-enable a stage excluded by `--tiers` or `--no-tier3`. The Dockerfile-, workspace-, resource-, and progress-tuning flags (`--custom-dockerfile-mode`, `--skill-workspace-mode`, the `--override-*` flags, `--progress`, and `--progress-interval`) are not forwardable — use the standalone [tier3 evaluate](#tier3-evaluate) command for those.
</Note>

| Flag | Default | Effect |
| --- | --- | --- |
| `--tier3 / --no-tier3` | enabled for skills | Run or skip Tier 3 live agent evaluation. Accepts a supported YAML/JSON dataset or native Harbor source and validates it before execution. `--agent-eval` / `--no-agent-eval` are compatibility aliases. Explicit `--tiers` selection controls scope; `--no-tier3` also disables autopilot. |
| `--block-on-agent-eval / --no-block-on-agent-eval` | advisory | Choose whether Tier 3 findings, including missing or invalid selected task-source evidence, participate in the `validate` exit gate. ## tier3 select-decoys

Choose neighboring skills from a local description-embedding catalog and save
a frozen JSON manifest for group evaluation. This command makes an embedding
request for the target; it does not launch an agent or modify the run policy.

```bash title="Save a group-workspace selection"
skillevaluator tier3 select-decoys ./skills/my-skill \
  --catalog ./skill-catalog.json --catalog-root ./skills \
  --count 4 --output ./skills/my-skill/evals/decoys.json
```

| Flag | Default | Effect |
| --- | --- | --- |
| `--catalog FILE` | required | Skill-only catalog with at most 1,000 entries, saved by `similarity-check --save-catalog` without `--full-body`. |
| `--catalog-root DIRECTORY` | required | Local collection root corresponding to catalog-relative skill paths. |
| `--count INTEGER` | `4` | Number of eligible skills to select, from `1` to `1000`; fails if fewer are available. |
| `--exclude PATH` | none | Exclude a catalog-relative skill path; repeatable. |
| `--model TEXT` | configured embedding model | Embedding model override; must match the catalog. |
| `-o, --output FILE` | required | Selection manifest to write, outside the collection or inside the target's `evals/` directory. |

The manifest records the catalog hash and embedding identity, selected paths
and scores, target manifest hash, and selected runtime-content hashes. The
target's own collection uses a root relative to its parent directory, so an
identical checkout can reuse the manifest. The hashes cover everything staging
copies from a selected skill, including ignored or untracked files and empty
folders, so generate a manifest you plan to commit from a fresh clone.
Unrelated external collections
retain an absolute root. Evaluator-only files are excluded from decoy hashes;
changing a decoy's evaluation config does not require a new selection. Output
cannot overwrite evaluation inputs or an existing non-manifest file. Set
`skill_workspace.mode: group` and `skill_workspace.decoy_manifest` in
`evals/config.yml` to consume it. The manifest path is relative to the target
skill's parent directory. Evaluation validates and reuses the selection
without contacting the embedding provider. See
[Select a reproducible decoy set](/skills/skillevaluator/agents-and-sandboxes#select-a-reproducible-decoy-set)
for a complete example and the limits of similarity-based selection.

Without a `--model`/`--agent-model` override, agent execution uses
`gpt-6.1-sol` for OpenAI (OpenCode: `openai/gpt-5.6-sol` unless

## tier3 validate-grader

Qualify the shipped Tier 3 verifier against independently labelled evidence.
See [Grader Validation](/skills/skillevaluator/grader-validation) for the versioned suite format,
denominators, provenance and interpretation.

```bash
skillevaluator tier3 validate-grader --check-suite
skillevaluator tier3 validate-grader ./suite --repeats 3 -o qualification
```

| Option | Default | Meaning |
| --- | --- | --- |
| `SUITE_DIR` | bundled reference suite | Directory containing suite.json |
| `--repeats N` | 3 | Positive number of grades per case |
| `--split assessment\|tuning\|all` | assessment | Split selection; all keeps statistics separate |
| `--case ID` | all selected cases | Repeatable case filter |
| `-o, --output DIR` | grader-validation-output | Empty output directory for JSON and attempt artifacts |
| `--json` | off | Print full report as JSON |
| `--check-suite` | off | Validate suite and executable labels; with a policy also check expected coverage, no provider/output writes |
| `--qualification-policy FILE` | unset | Explicit assessment-only coverage and risk policy JSON; no default policy |
| `--concurrency N` | 1 | Maximum concurrent verifier subprocesses |
| `--timeout SECONDS` | 300 | Positive per-attempt timeout |
| `--max-false-pass-rate RATE` | unset | Gate any reported metric's false-pass rate |
| `--max-false-fail-rate RATE` | unset | Gate any reported metric's false-fail rate |
| `--max-unjudgeable-rate RATE` | unset | Gate any reported metric's error/insufficient rate |

Rates must be between 0 and 1. Exit 0 reports results (including disagreement),
exit 1 means an explicitly supplied gate was exceeded, and exit 2 means invalid
usage, suite or provider configuration. Gates use assessment only with split all.

With `--qualification-policy FILE`, exit 1 also means failed or insufficient policy
evidence. Missing required metrics/rates and unmet distinct-case class/category
minima cannot pass; repeats and behavior steps do not add cases. The policy only
accepts `--split assessment` and cannot be combined with standalone `--max-*-rate`
gates; put its criteria in the policy file. These combinations are usage exit 2
before provider access. Offline `ready` means expected-label coverage only,
with scored counts/rates unobserved. Live insufficient preflight retains a
`not_run` receipt with no attempts before provider access. Covered live runs retain the
evaluated decision in JSON stdout and `grader-validation.json`. Policy identity,
canonical hash, effective definition, coverage checks and reasons are retained;
see [policy details](/skills/skillevaluator/grader-validation#explicit-qualification-policy).

## tier3 feedback

Chat in the terminal about one completed live-evaluation run: which cases
explain a score, how the skill compared with the baseline, and what to change
in the skill. Answers are grounded in that run's saved evidence: scores,
with-skill and baseline comparisons, every case's attempts with per-metric
scores, measured agent tokens and seconds, execution errors, and the report's
saved feedback. The run is not evaluated again, and the report's LLM feedback
is not generated again.

```bash title="Discuss a completed run"
skillevaluator tier3 feedback ./my-skill/evals/results/20260709_141530_12345_a1b2c3d4e5f6

# Name the evaluated skill explicitly
skillevaluator tier3 feedback ./my-skill/evals/results/20260709_141530_12345_a1b2c3d4e5f6 --skill ./my-skill
```

Pass one completed run directory, also when results live under a custom
`--results-dir`. The command infers the evaluated skill from the run. An
explicit `--skill` must name the skill directory the run recorded; when that
skill has changed since the run, the chat says so, and its answers describe the
evaluated version.

`tier3 feedback` always opens this chat, also in a directory that contains a
skill folder named `feedback`. To evaluate that skill, run
`skillevaluator tier3 ./feedback` or `skillevaluator tier3 evaluate feedback`.

| Flag | Default | Effect |
| --- | --- | --- |
| `--skill DIRECTORY` | inferred from the run | Evaluated skill directory. It must match the skill the run recorded. |

Ask, for example, "Which cases explain the lower score?" or "What should I
change if agent time matters more than token cost?" Treat proposed changes as
hypotheses and check them with another evaluation; answer quality depends on
the configured model. Type `exit` or press Ctrl-D to end the chat. Ctrl-C
during an answer discards that question and returns to the prompt.

The chat uses the provider and model configured for LLM checks
(`SKILL_EVAL_LLM_PROVIDER` and `SKILL_EVAL_LLM_MODEL`; see [Environment
Variables](/skills/skillevaluator/environment-variables)). Each question sends the run's compact
evidence to that provider. The evidence names the run by its ID instead of its
local path. In every text field, such as errors, warnings, case questions and
saved feedback, an absolute path that ends in the run's directory is replaced
with that ID. This covers the path a copied run had on the machine where it ran,
also when it starts with `~user/`, `$HOME/`, `${HOME}/` or `%USERPROFILE%\`,
unless that path contains a space. A path joined to it, such as `/usr/bin` in
`PATH=/usr/bin:/home/ci/results/RUN_ID`, is kept. A root right after `,` `;` `:`
`=` `(` `[` or `{` starts a new path, so a directory name that ends in one of
those characters before a `/` is read as two paths and only the second is
replaced. So does a root right after a `\n`, `\r` or `\t` escape in JSON or repr
text, such as the next line of an env dump, also with ANSI codes after the
escape, as on a progress line (`\r\u001b[K`); a relative path after one is kept,
and a UNC server name that starts with `n`, `r` or `t`, such as `\\nas01\share`,
is not read as an escape. A path may also start right after an ANSI code, such
as the color code `\u001b[0m` or the erase-line code `\u001b[K`, and a path
colored in parts is replaced whole. The evaluated skill's directory is replaced
with its name and your home directory with `~`; the skill directory is known
when you pass `--skill` or the run is in the skill's `evals/results` directory.
Path masking leaves a URL unchanged, even a path in its query or fragment,
unless its scheme is `file:` or ends in `+file:`, such as `git+file:`. A URL
ends at whitespace; at a quote, `<`, `>`, a backtick, `^`, `{`, `|`, `}` or an
ANSI escape (raw, `\u001b` or `\x1b`); at a `\n`, `\r` or `\t` escape; and
before an absolute path or another scheme that follows a `,` or `;` (also with
an option or variable name and `=`, such as `LOG=` or `--find-links=`) or a
Markdown `](`. So a path after a URL in JSON, on the next line of an escaped env
dump or stderr, in a `,`- or `;`-separated list or in
`DOC=https://host/e;LOG=/path`, and a `file:` URL listed after one, are still
replaced. A path joined to a URL by any other character, such as `:`, `=`, `(`
or `)`, is not. The escape may have a doubled backslash, as in JSON inside JSON.
A backslash and `n`, `r` or `t` that start a Windows folder name made of
letters, digits, `_`, `.`, `~`, `$`, `%` or `-` and followed by as many
backslashes, such as `\runs\` or `\t\` (`\\runs\\` in JSON), are not an escape
unless an escaped character such as `\u001b` or `\xa0` comes next and is not
itself followed by a name and as many backslashes, so a Windows path with such
folders, such as `\t\x64\runs\`, in a URL is kept. Any other folder or file name
that starts with `n`, `r` or `t`, such as `\runs(old)\` or `\notes.txt`, ends
the URL there. Credential-shaped text is redacted before the text is shortened,
and a shortened field ends in `...<truncated>`. The command writes nothing to
disk.

No request is sent before the first question, so the command exits 0
immediately when standard input is empty. Piped input sends each line as a
question, and each one is a paid request. The command exits 1 when the run or
provider configuration cannot be used, or when questions were asked and every
one of them failed.

## doctor

Check live-evaluation runtime readiness: the CLI install, the configured provider, the requested agents and their credentials, and the selected backend. Run it before your first `tier3 evaluate` — see [Agents & Sandboxes](/skills/skillevaluator/agents-and-sandboxes) for what each check means.

```bash title="Deep readiness check"
skillevaluator doctor --env-mode docker
```

`--tier` selects other readiness checks. Without it, `doctor` checks Tier 3 only, as above.

```bash title="Tier 1 scanners and Tier 2 providers"
skillevaluator doctor --tier 1 --checks security,code-integrity,dependency
skillevaluator doctor --tier 2 --verify-models
skillevaluator doctor --tier all
```

- **Tier 1** reports each external scanner the selected checks run: SkillSpector for `security`, Bandit, Semgrep and Gitleaks for `code-integrity`, and pip-audit for `dependency`. Each row shows the resolved executable, the override variable when one selected it, and the version from a bounded version probe. The probe never starts a shell. A scanner fails when it is missing, its override is malformed, or the probe exits nonzero or times out. It also fails when it is older than the release the validators parse: Bandit 1.9.4 or Gitleaks 8. An unreported version is a warning.
- **Tier 2** checks that the embedding provider and the LLM provider used for duplicate analysis resolve, without a network request. With `--verify-models`, it also sends one embedding request and one chat request, each bounded by `--timeout` and sent without retries. Failures show only the HTTP status and a remedy, never the provider's response body.
- **all** runs Tiers 1, 2 and 3 in order. A failed tier does not stop the next, and the exit code is nonzero when any tier fails.

An option for a tier that is not selected exits with a usage error before any check runs. For example, `--checks` without `--tier 1` or `all` is an error, and so is `--timeout` with `--tier 2` but no `--verify-models`, because offline Tier 2 sends no request.

| Flag | Default | Effect |
| --- | --- | --- |
| `--tier [1\|2\|3\|all]` | `3` | Readiness to check: Tier 1 scanners, Tier 2 providers, Tier 3 live evaluation, or all three in order. |
| `--checks TEXT` | `validate`'s default checks | Tier 1 only. Comma-separated checks whose scanners to probe, with the same names as `validate --checks`; add `dependency` to include pip-audit. |
| `--timeout FLOAT` | `60` | Tier 1, and Tier 2 with `--verify-models`. Seconds allowed for each scanner version probe and each Tier 2 live request, including a Bedrock chat request; must be finite, greater than 0 and at most 3600. |
| `-a, --agents TEXT` | provider-native | Comma-separated agents to check. Defaults: NVIDIA Build=`opencode`, OpenAI=`codex`, Anthropic=`claude-code`. |
| `--env-mode` | `docker` | Backend to check (same 27 modes as [tier3 evaluate](#tier3-evaluate)). |
| `--backend [harbor\|nemo-gym]` | `harbor` | Execution backend to check, as in [tier3 evaluate](#tier3-evaluate). `nemo-gym` checks the Gym CLI, the Docker daemon, the `SKILL_EVAL_NEMO_GYM_*` settings and each agent's policy endpoint. |
| `--environment-kwarg`, `--ek` | none | `KEY=VALUE` non-secret constructor option for a Harbor-native non-Docker backend (repeatable). Pass the same values intended for evaluation. Docker and local reject all kwargs, and Kata accepts only `kata_runtime` and `kata_dns`; policy-owned fields are rejected for every eligible backend. |
| `--agent-model TEXT` | unset | Per-agent model override, `AGENT=MODEL` (repeatable) — check readiness with the model each agent will actually run. |
| `--verify-models` | off | Tier 3: live per-agent catalog probe. Prints pass for verified access, warn for an inconclusive or non-authoritative result (success or failure), and fail only for a definitive credential, model, or configuration rejection. Tier 2: one embedding and one chat request. |

`-a`, `--env-mode`, `--backend`, `--environment-kwarg` and `--agent-model` apply to Tier 3 only. `skillevaluator tier3 doctor` checks only Tier 3. It takes the Tier 3 flags, including `--agent-model` and `--verify-models`, and has no `--tier`, `--checks` or `--timeout`.
