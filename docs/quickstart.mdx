---
title: Quickstart
description: Install SkillEvaluator, configure one provider and key, and run all three tiers or one tier independently.
---

Set a provider and its key, then run `validate ./my-skill` for all three tiers.
Default models are already configured for NVIDIA Build and OpenAI.

## Install and configure

<Steps>
  ### Install

  [uv](https://docs.astral.sh/uv/) provisions Python 3.13 and installs every
  Python evaluation extra:

  ```bash title="Install with uv"
  uv tool install --python 3.13 "skillevaluator[all] @ git+https://github.com/NVIDIA/SkillEvaluator.git"
  skillevaluator --version
  ```

  <Tip>
  If the shell cannot find `skillevaluator`, run `uv tool update-shell` and
  open a new terminal.
  </Tip>

  ### Set the provider and key

  These two variables configure NVIDIA Build for all three tiers:

  ```bash title="NVIDIA Build"
  export SKILL_EVAL_LLM_PROVIDER=nv_build
  export NVIDIA_API_KEY='nvapi-...'
  ```

  Get a key from [build.nvidia.com](https://build.nvidia.com/). That same key
  covers evaluator chat, Tier 2 embeddings, and supported Tier 3 agents in
  Docker or local mode. No model or embedding settings are required.

  For OpenAI, use `SKILL_EVAL_LLM_PROVIDER=openai` and `OPENAI_API_KEY` instead;
  the default Codex agent uses the same OpenAI key. Other providers and optional
  model overrides are covered in [Providers & Credentials](configuration.mdx).

  ### Install the runtime tools

  Full Tier 1 scanner coverage needs Semgrep, SkillSpector, and Gitleaks in
  addition to the Python extras:

  ```bash title="Tier 1 scanner setup on macOS"
  brew install semgrep gitleaks
  uv tool install git+https://github.com/NVIDIA/SkillSpector.git
  ```

  See [Installation](installation.mdx#system-tools) for other platforms.
  Tier 1 exits `0` when its selected checks pass. A failed check exits `1`;
  missing scanner evidence leaves the result `INCOMPLETE` and exits `1`.

  Tier 3 needs a supported agent runtime and a running sandbox (Docker by
  default). Check those prerequisites before the first live run:

  ```bash title="Tier 3 readiness"
  skillevaluator doctor --env-mode docker
  ```
</Steps>

## Run all three tiers

Point `validate` at a directory containing a `SKILL.md`:

```bash title="Validate a skill"
skillevaluator validate ./my-skill
```

This runs Tier 1 checks, Tier 2 deduplication, and Tier 3 live evaluation.
Tier 3 uses autopilot: it reuses valid existing evaluation sources or generates
one starter case when none exists, then evaluates with and without the skill.
`--full` remains supported but is not required. Use `--tiers 1,2` to skip the
live evaluation, or `--no-autopilot` to require an existing source.

Tier 1 and Tier 2 gate the result by default. Tier 3 is advisory unless you
add `--block-on-agent-eval`; that setting affects the exit code, not whether
the live evaluation runs.

## Run one tier

Point each command at a directory containing a `SKILL.md`. Each tier is
independent; it does not require running earlier tiers first.

```bash title="Choose the evaluation you need"
skillevaluator tier1 ./my-skill
skillevaluator tier2 ./my-skill
skillevaluator tier3 ./my-skill
```

| Command | What it runs |
| --- | --- |
| `tier1 PATH` | All static checks, including dependencies; with a provider, rubric judging, LLM security analysis, and finding verification also run |
| `tier2 PATH` | Intra-skill deduplication; add `--catalog ./skill-catalog.json` for inter-skill comparison |
| `tier3 PATH` | Creates one starter case when the evaluation source is missing, then runs the provider-native agent with and without the skill |

Without a catalog, Tier 2 explicitly reports that inter-skill comparison did
not run. Build a reusable catalog with
`skillevaluator similarity-check ./skills --save-catalog ./skill-catalog.json`.

Tier 3 reuses valid existing datasets or task sources without rewriting them;
invalid sources produce an error. The generated starter case is enough to try
the pipeline, not to establish broad coverage. Generate and review a larger
dataset with `skillevaluator tier3 create-eval-dataset ./my-skill --full`.
Without `--agents`, Tier 3 selects OpenCode for NVIDIA Build, Codex for OpenAI,
and Claude Code for Anthropic. An explicit `--agents` value always wins.
Live evaluations make paid model calls; see
[Tier 3: Plan for cost](tier3-live-evaluation.mdx#plan-for-cost).

A tier without a path shows help. Expert subcommands remain available, such as
`skillevaluator tier1 security-scan ./my-skill` and
`skillevaluator tier3 evaluate ./my-skill`. No `run` subcommand is needed.

## Try a keyless check

You can start before configuring a provider:

```bash title="Deterministic quality score"
skillevaluator quality-check ./my-skill
```

This prints a score from 0–100 and an A–F grade, passing at 70 by default.
For the static Tier 1 suite, use `skillevaluator tier1 ./my-skill --no-llm`.
Scanner tools still need to be installed. Without a provider, direct Tier 1
also runs the static suite and reports the LLM stages as skipped; it does not
claim those stages passed.

| Check quality and security | `tier1 ./my-skill` | [Tier 1: Validation](tier1-validation.mdx) |

For rules, workflows, and plugins, `validate` runs their applicable validation
stages without automatically enabling live skill evaluation.
