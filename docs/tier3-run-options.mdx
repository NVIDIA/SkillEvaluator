## Before you run

- [Install SkillEvaluator](/skills/skillevaluator/installation#all-tiers) with the all-tier option.
- Configure a [model provider](/skills/skillevaluator/configuration) and start Docker.
- Have reviewed cases in `./my-skill/evals/evals.json`. [Prepare your dataset](/skills/skillevaluator/prepare-dataset) if it is missing.

```bash title="Check the dataset and runtime"
skillevaluator tier3 validate ./my-skill --strict
skillevaluator doctor --env-mode docker
```

Treat a missing dataset as **not ready**, even if validation exits `0`. Fix
errors and warnings before continuing. Native task bundles use
the [task workflow](/skills/skillevaluator/custom-graders) instead of `evals.json`.

## Choose a run

<Tabs>
  <Tab title="First comparison">

```bash title="Use your provider's default agent"
skillevaluator tier3 evaluate ./my-skill --env-mode docker --n-attempts 1
```

Runs one attempt per selected case in each arm: with the skill and without it.
This explicit command requires an existing evaluation source; it does not
create a missing dataset unless you add `--autopilot`.

  </Tab>
  <Tab title="Choose an agent">

```bash title="Example: use Codex with an OpenAI provider"
skillevaluator tier3 evaluate ./my-skill --agents codex --env-mode docker --n-attempts 1
```

Configure OpenAI before using this example. For OpenCode, Claude Code, or a
model override, follow [Agents & Sandboxes](/skills/skillevaluator/agents-and-sandboxes).

  </Tab>
  <Tab title="Repeat attempts">

```bash title="Try each case up to three times"
skillevaluator tier3 evaluate ./my-skill --env-mode docker --n-attempts 3 --stop-on-pass
```

A passing attempt stops the remaining attempts for that case. This can still
use more model calls than a single-attempt run. `--stop-on-pass` requires more
than one attempt.

  </Tab>
</Tabs>

<Note>
  Model and sandbox usage can incur charges. Planned trials are
  **cases × agents × attempts × 2 arms**; each trial can make multiple model
  calls. Attempt count does not limit the number of selected cases. Keep the baseline enabled when
  you need Skill Lift.
</Note>

<Accordion title="Use an existing run configuration">
  Settings in `evals/config.yml` still apply. Check `harbor.max_cases` and
  budget settings before assuming the run covers the full dataset.
  See [run policy](/skills/skillevaluator/eval-datasets#run-policy-evalsconfigyml).

  If that file enables `harbor.stop_on_pass`, turn it off when switching to
  one attempt:

  ```bash
  skillevaluator tier3 evaluate ./my-skill --env-mode docker --n-attempts 1 --no-stop-on-pass
  ```
</Accordion>

## Read your result

```bash title="Open the latest report"
skillevaluator view ./my-skill
```

| Check | What to do |
| --- | --- |
| Run status and coverage | Resolve missing or failed trials before interpreting improvement. |
| Skill Lift | Compare scored outcomes across the same cases in both arms. |
| Trial details | Inspect failures, skill activation, and outputs before changing the skill. |

Reports are written under `./my-skill/evals/results/` by default.
[Interpret the report](/skills/skillevaluator/tier3-results).
